## 1. What it is

**SuperBrain — "AI-powered save-it-later brain for Instagram, YouTube & Web."**
A self-hosted personal content archive: you share a URL (Instagram post/reel, YouTube
video, web page) from any app into SuperBrain; a Python backend downloads/extracts it,
runs multi-provider AI analysis (summary, tags, category, transcription, music ID), and
the Android app becomes a searchable, collection-organized feed of everything you saved.

- Repo: https://github.com/sidinsearch/superbrain — description verbatim: *"SuperBrain — AI-powered save-it-later brain for Instagram, YouTube & Web"*
- Homepage: https://superbrain.sidx.dev/ (from GitHub API)
- **Important framing for brainkit:** despite the name, this is NOT a knowledge-wiki /
  note tool. It is a content-capture + AI-enrichment + retrieval product. Its overlap with
  brainkit is the *ingestion → enrichment → organize → search* loop and the polish of its
  capture/browse UX — not compiled knowledge, provenance, or graphs (it has **no graph
  view at all** — verified against the full file tree; no graph component exists).

6. Audio transcription — `backend/analyzers/audio_transcribe.py` (Groq Whisper API, local Whisper fallback; model choice in `config/whisper_model.txt`).
7. Background-music identification — `backend/analyzers/music_identifier.py` (Shazamio); surfaced in PostDetail with a streaming link when available.
8. Visual/frame analysis — `backend/analyzers/visual_analyze.py` (OpenCV frame extraction per README) + `caption.py`, `text_analyzer.py`.
9. Processing queue with automatic retry — `processing_queue` table (`backend/core/database.py`) with `status queued/processing/retry`, `retry_after`, attempt counts; endpoints `/queue-status`, `/queue/retry`, `/queue/retry/flush`, `DELETE /queue/{shortcode}` (`backend/api.py`). **Organization & retrieval**
10. Collections (Watch Later + custom) — `collections` table; `superbrain-app/src/services/collections.ts`; `LibraryScreen.tsx`, `CollectionDetailScreen.tsx`; Watch Later is a seeded, undeletable default (`default_watch_later`, deletion blocked in `api.py`).

14. Offline-first with delta sync — `syncService.ts`, `postsCache.ts`, `localDb.ts` (details §6).
15. Data portability — `GET /export` (JSON or ZIP with embedded thumbnails), `POST /import` (merge/replace), `POST /import/file`; `DataImportExportScreen.tsx`.
16. Failed-analysis triage — `FailedAnalysisScreen.tsx` + red warning card at the top of LibraryScreen linking to it; retry per item.
17. Soft delete + restore + deletion sync — `is_hidden` flag, `deleted_log` table, `restore_post()`, `GET /sync/deleted` (`database.py`, `api.py`).
18. QR-code pairing — `GET /connect-info` returns URL+token for mobile QR scanning (`api.py`); `QRScannerScreen.tsx`; manual URL + 8-char token entry as alternative (`SettingsScreen.tsx`).
19. In-app AI provider management — `AIProviderScreen.tsx` + `/settings/ai-providers` GET/POST/DELETE with key validation; `GET /router-status` exposes live ranking/latency/fallback order.
20. Browser extension bulk import — `superbrain-extension/`: content script auto-scrolls Instagram's saved-posts page, extracts URLs, recreates matching collections server-side; popup shows real-time progress log (extension README).
21. One-line server install — `npx -y superbrain-server@latest` (`superbrain-cli/bin/superbrain.js`), Docker compose, or interactive `start.py` setup wizard + `reset.py`.

### 4.3 Implemented vs advertised

- Genuinely implemented: everything above traces to concrete source files with plausible
  line counts; codemaps in `docs/CODEMAPS/` match the tree.
- Overstated in README: **"Full-text search" is LIKE-substring matching, not FTS**
  (§3.11). "Offline-first" is real for reads and post-mutations but the sync service
  itself is one-directional server→local with a separate pending-mutation flush
  (`postsCache.flushPendingPostMutations()` called from HomeScreen), not a general
  bidirectional conflict-resolving sync.
- Not present at all despite the "second brain" topic tag: no knowledge graph, no
  note-linking, no wiki, no embeddings/vector search (nothing in the tree suggests any).

## 5. Distinctive functionality worth noting

- **Watch Later reminders with deterministic time slots** (`notificationService.ts`):
  `simpleHash(shortcode) % 28` maps each post to one of 28 half-hour slots between
  8:00 and 21:30 — every saved item gets its *own* stable daily reminder time instead of
  one bulk digest. Deadline-looking posts (regex: "deadline", "exam", "contest",
  "apply") additionally get a high-priority ~9 AM urgent alert. Three Android channels
  (watch-later / watch-later-urgent / analysis-complete); "Mark as Watched" action
  button removes the post and cancels its notifications; IDs mapped per shortcode in
  AsyncStorage for cancellation.
- **Live router transparency**: `GET /router-status` exposes the model ranking, EMA
  latencies, fallback order and metrics — the AI plumbing is inspectable from the app.
- **Zero-friction pairing**: server prints/serves `/connect-info`; phone scans a QR and
  is connected. Token is a human-copyable 8-char code as fallback.

## 6. Performance & engineering techniques (backend)

From `backend/core/model_router.py` (~1,200 lines):
- Sequential fallback chains (text: Groq → Gemini → OpenRouter-free → Ollama; vision:
  Gemini → Groq → OpenRouter → Ollama), **not** parallel racing.
- **EMA latency ranking**: `new_avg = 0.3·latency + 0.7·prev`; effective priority =
  base + `min(10, max(0, (avg_s − 2.0)/3.0))` — every 3 s over a 2 s baseline costs one
  priority point; unmeasured models keep base priority (optimistic until proven slow).
- **Tiered cooldowns**: HTTP 429 → 30 min down; generic error → 5 min. `down_until`
  checked before routing.
- **Persistent state**: `config/model_rankings.json` (EMA, success/failure counts,
  cooldown expiry, last error) saved after every outcome, restored on start.
- **Dynamic free-model discovery**: OpenRouter free models refreshed every 6 h by a
  background thread, scored 0–1 (context 40% / capabilities 30% / recency 20% /
  provider trust 10%), top 30 cached to disk, injected after static models.

From `backend/core/database.py` (~750 lines):
- SQLite WAL + FK pragmas; six targeted indexes (category, analyzed_at DESC, queue
  status/position/retry, deleted_log, content_type).
- **Light-columns projection**: `LIGHT_COLUMNS` excludes the heavy blobs
  (visual_analysis, audio_transcription, text_analysis) from list endpoints; detail
  fetch gets the rest. `/recent` is paginated on the light projection.
- **Delta sync protocol**: `get_posts_since(updated_at > ts)` ordered ASC +
  `get_deleted_since(ts)` from the `deleted_log`; the client (`syncService.ts`, ~250
  lines) keeps a cursor, batches with offset, caps at `MAX_SYNC_PAGES = 50`, detects a
  non-advancing cursor to avoid infinite loops, and only advances the cursor on a
  complete sync. Full sync only on first launch / reset / taxonomy version change.
- Retry queue uses `retry_after` timestamps rather than polling; soft delete via
  `is_hidden` keeps sync-safe tombstones in `deleted_log`.

App side: AsyncStorage post cache read *before* network (UI renders instantly), pending
mutation/analysis flush queues, taxonomy fetched once behind a shared promise.

## 8. What brainkit should conclude (synthesis)

SuperBrain's magnetism is not its data model (which is a single `analyses` table) — it's
that **every stage of the pipeline is visible and touchable in a polished dark UI**:
capture appears instantly as an "analyzing" card, failures are a tappable red card with
a retry, the AI router shows its ranking, settings validate on save, and every list has
a designed empty state. brainkit has a strictly stronger engine (immutable evidence,
provenance-cited wiki, real FTS, graphs, privacy boundaries) and a much thinner face.
The highest-leverage adoption is a **vault feed + status UI** over the data brainkit
already maintains (registry, freshness ledger, FTS index, graph.json), in superbrain's
visual language — with zero engine changes.
