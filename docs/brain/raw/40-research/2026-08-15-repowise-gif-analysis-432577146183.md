# Synthesis

## (a) Information architecture

Global shell = persistent **left sidebar** with three tiers: app-global (Dashboard, Settings, Search ⌘K), **workspace → repositories** (multi-repo, one active repo with an orange status dot), and **per-repo sections** in three labeled groups:

- Repo views: **Overview → Docs → Architecture → Knowledge Graph → Code Health → Refactoring → Files**
- `PEOPLE & HISTORY`: **Commits, Contributors, Decisions, Chat**
- `SETTINGS`: **Stats, Usage & savings**

Movement patterns seen: sidebar click (view switch, breadcrumb updates), **in-page drill-down** (health summary → map zoom via fade-in-place), **drawer** for a single finding (Refactoring → Break Cycle), **modal on top of the drawer** (prompt composer — two stacked overlay layers), and two **mode switches** that replace the chrome: Docs (own secondary sidebar + toolbar + reading typography) and Present (chrome-free deck with Deck/Walkthrough tabs). Breadcrumbs (`Dashboard › repowise › View`) keep the hierarchy legible everywhere except the two immersive modes.

## (b) UI element inventory

- **Navigation:** sidebar with grouped micro-label sections; icon-only collapsed rail; secondary docs tree sidebar; breadcrumbs; tab bar **with count superscripts** (Findings ⁵⁰⁴²); segmented lens switcher (Health/Maintainability/Performance/Churn); Deck/Walkthrough mode tabs; prev/next circular buttons + dot progress strip.
- **Actions:** tan filled primary buttons (Sync, Generate code, Copy prompt, Copy prompt for an agent); outlined secondary buttons (Refresh, Help us improve); text links with `→` (Full health report, All commits, Open layer.ui in reader); `…` overflow; ✕ close; "Change model" muted link; Light/Dark segmented toggle; "Clear selection" control.
- **Containers:** right-side detail drawer with sticky footer; centered modal over scrim; hint/help card; before/after diptych cards joined by a circled arrow; selectable target-agent cards (2×2, border = selected); stat cards separated by dotted hairlines; KPI strips divided by hairlines.
- **Data display:** giant score numeral + "out of 10" + Good pill; stacked distribution bar with dot legend (alert/warning/healthy + counts); thin progress bar; ranked findings list (dot + mono filename + small-caps category + signed score); commit rows (hash chip + message + relative time); decision rows with `active · 3d ago` status; metadata chip rows (language dot, branch, hash, LOC, synced-ago); count chips (+3 files, 3703 pages); token/char cost line (`2,714 chars · approx 673 tokens`); badge rows (`Large effort · Medium confidence · 7 files affected · No score change`).
- **Visualizations (4 distinct engines):** circle-packed **module galaxies** (node = file, size = LOC, color = health, labeled cluster chips, legend strip); **circular co-change chord diagram** with edge bundling, sector labels and pinned-trace highlighting; small **ring dependency-cycle diagram** (drawer); **C4 architecture diagram** on grid paper with dashed boundary boxes and edge weights; plus the sparkline-like progress bars.
- **Docs surface:** serif article with TOC rail, "On this page" active indicator, SIGNALS/RELATED micro-sections, model byline (`Written by gpt-5.4-nano`), freshness pill (`✦ Fresh`), Regenerate/Export/Present toolbar.
- **AI surfaces:** prompt preview pane (mono, scrollable), target-agent picker, model attribution lines, agent-savings stat, per-prompt token pricing.
- **Misc:** search inputs with placeholder + ⌘K chips; dropdown filters (All pillars/All severities); caption/subtitle pill (marketing overlay, not app UI); version string; feedback button.

## (c) Design language

- **Mode:** light, warm **paper/cream** theme (a Dark toggle exists but is never shown).
- **Estimated palette:** app background `#F7F3EC`–`#F4EFE6` (warm off-white); cards/panes `#FCFAF5`; hairlines/dotted rules `#E5DFD2`; primary text near-black warm `#2B2723`; muted text `#8A8378`; **accent ochre/tan `#C08A3E`–`#B98A44`** (primary buttons, active nav, links, selection borders); **score green `#2E6B4F`** (numerals, healthy dots, Good pill); alert orange `#C9762B` and warning amber `#D9A441`; alert red used sparingly in legends; deck canvas `#EFE7DA`; browser-mockup surround `#2A1E16` (dark chocolate); caption pill near-black `#1C1A17` with white text.
- **Elevation & shape:** almost flat — hierarchy by hairlines, dotted separators and background tints rather than shadows; soft shadows reserved for overlays (drawer, modal, caption pill). Radius habits: small (6–8 px) on buttons/chips/cards, pill radius on badges/toggles/caption; generous whitespace, airy line-height.
- **Typography (3 deliberate roles):** humanist sans for UI; **mono small-caps micro-labels** for every section eyebrow (`CODE HEALTH`, `TARGET AGENT`, `THE CHANGE`…) and for filenames/hashes/paths; **serif display** for the docs article and deck titles (book-like reading mode). Numbers get big-and-bold treatment with tiny unit suffixes (`7.5 out of 10`, `3,713 pages`, `51K`).
- **Voice as design:** every stat card carries a one-sentence plain-English explanation ("Tokens your agent did not spend, priced at claude-opus-5"); prose uses bold inline emphasis for the numbers that matter. Honesty microcopy is a pattern ("a temporal hint … not a verified code dependency", "No score change", "Medium confidence", "treat them as leads to investigate, not commands to execute").
- **States seen:** active nav pill (beige bg + orange text), selected card (tan border), pinned/trace highlight (colored chords vs faint grey), Fresh pill (green dot), disabled/muted chrome under scrims. No loading/empty states appear in the demo. **Uncertain:** hover states (GIF too coarse to catch them).

## (d) Top-5 lovable UI moments

1. **The graded-score hero with a receipt (Scene 1/2).** A huge green **7.5 / Good** that immediately explains itself in prose with bold inline numbers — and then *validates itself against reality*: "19 of the 20 files it scores worst were touched by a real fix… 3.29× better than random." A metric UI that argues for its own credibility is rare and instantly trustworthy.
2. **Module galaxies (Scene 3).** 3,116 files as circle-packed, labeled, health-colored galaxies with a lens switcher that "recolors the same field rather than redrawing it" — a whole-codebase gestalt in one glance, gorgeous in the warm palette (green/amber dots on cream).
3. **The Break Cycle before/after diptych (Scene 4).** TODAY (a literal ring of 7 files) → AFTER (scissors-icon rows of exact import edges to cut), plus effort/confidence/blast-radius badges and "WHAT YOU GAIN" bullets. It turns an abstract graph problem into a surgical, priced decision card.
4. **"Copy prompt for an agent," priced in tokens (Scene 5).** Target-agent cards (Generic/Claude Code/MCP/Cursor), a real prompt preview with investigate-don't-trust framing, and the footer `2,714 chars · approx 673 tokens`. The analysis tool hands its findings to your coding agent as a contract — the most contemporary beat in the demo.
5. **Docs → Present (Scenes 7–8).** The same data re-skinned as a serif wiki (model byline, Fresh pill, Regenerate) and then, one click later, as a chrome-free C4 slide deck with prev/next and a progress strip — closing on "No API key. No upload. localhost:3000." One dataset, three registers: dashboard, book, deck.

## (e) What ports well onto brainkit's web SPA

Brainkit's SPA (stdlib-served dark theme, three.js provenance graph, five views, chat, capture modal, toasts, FTS5 search, pipeline states, freshness ledger, code graph) could adopt, in rough order of value-per-effort:

1. **Self-explaining stat cards** (mono micro-label → big number → one-sentence plain-English explanation, dotted separators). Brainkit already has the numbers: sources registered, pages, pending proposals, index size, freshness distribution. This is pure HTML/CSS and would give the graph view an Overview rail like Scene 1's.
2. **Tab counts as superscripts** (`Findings ⁵⁰⁴²`): trivially applicable to brainkit's five views (Sources ⁿ, Pages ⁿ, pending proposals count on Timeline) — ambient inventory without opening a view.
3. **The finding-detail drawer with a sticky "Copy prompt for an agent" footer** (Scenes 4–5). Brainkit's lint findings (stale pages, uncited claims, dead links) and code-graph results (`bk code affected`, cycles) map 1:1 onto the Break Cycle card shape: badges (effort/confidence/files affected), before/after, "what you gain," then a copyable, token-priced prompt targeting Claude Code — which brainkit's users literally run. This is the single most brainkit-shaped idea in the demo.
4. **Freshness as a first-class pill + byline** (`✦ Fresh`, `Written by <model> · updated 3d ago`, plus a `Doc freshness` toolbar entry): brainkit's freshness ledger already stores exactly this; surfacing it as a per-page pill with age states (fresh/review/stale) in the pages view is a direct port.
5. **Honesty microcopy as a design pattern** ("a temporal hint, not a verified code dependency", "No score change", confidence badges): matches brainkit's whole ethos (provenance, citation-gated writes) and costs only words.
6. **A "lens" switcher on the existing 3D graph** — recolor the same node field by branch / freshness / consumer-visibility / pipeline state instead of redrawing, exactly like the Health/Maintainability/Performance/Churn control.
7. **Present mode** — a chrome-free deck generated from wiki pages (brainkit already renders pages + a graph; a serif slide with the neighborhood subgraph beside prose is Scene 8 verbatim).
8. **Caution on the palette:** repowise's warm-cream light theme is lovely but brainkit is a committed dark SPA; the portable part is not the cream but the *system* — one accent (ochre) reserved for actions/active states, one semantic green for "good/fresh", hairline-and-tint hierarchy instead of shadows, mono small-caps eyebrows, and big numerals with tiny units. All of it translates to dark tokens directly.
